# 云端模型配置与单次接口验证

2026-11-04，0.10.1 发布后的开发源码。新增命令行配置预检、临时单次测试和显式现代
Chat Completions 配置档。操作方法集中在[模型服务指南](../../model-providers.md)；
这里记录本次验证范围，不表示已升版、安装或发布这些改动。

## 配置入口

`--base-url` 纯解析 API 基址，保留前缀并追加 `/chat/completions`，不猜 `/v1`；
完整地址继续使用 `--endpoint`，两者互斥。危险或歧义路径、完整接口误作基址均拒绝。
`check` 与 `configure --dry-run` 不联网、不读密钥值、不写配置，帮助入口不依赖配置可读。
`probe --once` 默认英文首个固定样例，临时覆盖不保存；切换目标仍撤销旧云端授权。

现代 `chat-completions` 配置档显式发送 `max_completion_tokens` 与
`reasoning_effort: "none"`，保留温度与既有候选/翻译各自的 token 预算。
它不根据模型名或服务域名分支，旧 Auto、Ollama 和 compatible 请求保持原样。
规范依据为 [Chat Completions 参数](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)
和[推理兼容说明](https://developers.openai.com/api/docs/guides/latest-model)。

未知命令参数不再回显可能误传的内联密钥。翻译 live 测试先确认显式配置位于临时目录，
对同一已打开文件句柄校验普通文件并限读 65536 字节，不回退个人设置；原 Local-only、
八目标非空断言和显式忽略保留。链接换向及校验后文件增长另有回归。

## 日语名词分类与在途云请求取消

前一节六次实测发现的“日本語力”“日本語訳”误分类，已冻结为无类型适配器回执，
经真实候选 worker 与混排重放。第一次红测为 7 项中 4 项失败，均把名词标成句子；
修复只作用于新的、无类型提示的日语模型候选。整体限 2–8 个汉字，单个名词后缀前的
完整词干须为既有日语 Word；不修改公开离线分类、已有本地同文项、显式模型类型或其他语言。

云端从阻塞式等待改为同一 worker 内的异步 Client 与 current-thread Runtime，继续复用连接，
不为每次编辑另起请求线程。发送和有界正文读取共用一个 future，每约 25 ms 检查取消；
准备、发送、读体及 UTF-8 解码仍消耗同一绝对期限，轮询前后都复核取消和期限，防止一次轮询
跨过期限后误收成功。取消只结束本机在途等待，不能撤回已发送内容或保证远端计算、计费、
底层已启动的 DNS 解析立即停止。检查间隔不是实时输入延迟保证。
