# 0.8.6 安装与多样输入任务验证 2026 10 11

0.8.6 的中英日词库、复合输入、键盘、浏览器和 Qt 私有应用检查通过后，
按用户授权把日常用户级安装从 0.8.1 升级到 0.8.6。四个程序、实际运行宿主和
注册路径均已核验，Rime 与个人配置保留。远端 Linux CI 首次超时仍是失败记录，
不以本机通过替代远端验收，也没有发布 Release 安装包。

## 测试安装来源

四个优化程序来自干净提交 `81bbce81fed2fba6de9a2c954a41067a31237239`，与
`v0.8.6` 一致。先生成并检查二进制 tar，再解压到独立目录测试；不混用源码 debug
程序、日常 0.8.1 宿主或不同版本的探针。构建及重型测试串行执行，单构建任务，
MemoryHigh 2 GiB、MemoryMax 3 GiB、MemorySwapMax 0。

本机包目标为 `x86_64-unknown-linux-gnu`，manifest 的 `source_dirty=false`，
构建 libc 是 **glibc 2.43**。外层 SHA-256 为
`d0e197078b824fd668eaa6179306406761f5de5e6167f54e23da2f61da584f4a`；
内层校验及包内容检查通过。包不含模型权重和用户数据。这不是 Ubuntu 24.04
干净容器或通用二进制兼容性验收，也没有叠加系统级 `.deb` 安装。

## 独立安装的私有输入任务

应用按键和鼠标操作仅发生在新建 Xvfb、D-Bus、IBus、配置和合成文档中，
检查实际应用文本、未提交草稿、采用撤回和精确单次提交。
原生门禁的键事件通过私有 IBus 协议和订阅观察，不等同于 GUI 逐键或真实模型检查。
测试没有向个人桌面应用注入按键，没有改变个人键盘布局或锁定状态。

## CI 超时与测试分区

[0.8.6 CI](https://github.com/chiharu-kiryu/Suzaku-map/actions/runs/38120502423)
的 Linux 原生检查在 120 秒整套会话限制处以 124 退出。77 条 HTTP 回退子例已有
PASS，最后一条是第 39 个样例的 HTTP 503；对应 timeout 及其余 28 个子例未完成。
超时后原生控制组以及后续 UI、应用、打包、容器安装步骤没有通过证据。
格式、秘密扫描、macOS 和 Windows 检查通过，不代表 Linux 或发布全绿。

测试编排改为构建一次、分别执行核心与完整回退两个独立会话，每个仍限 120 秒。
原 53 × 2 回退函数、默认前段和后续控制的 AST 指纹锁定了原断言，500 ms 模型期限、
5 秒等待与所有失败路径不变。16 个专项模式的 120 种两两冲突均被拒绝；
任一分区失败就非零退出，专项通过不能报告完整门禁通过。
轻量检查 19 项、GTK3 事件观察检查 9 项、张量检查 21 项通过，
242 个仓库审计报告链接、Bash 语法和差异空白检查通过。
ShellCheck 未安装，不记为通过。

新编排在本机首次完整执行通过，106 条回退日志互不重复，两类故障各 53 条。
宿主、探针和工具来自已测干净包；原生激活使用源码构建的面板测试程序，
它与下节实际安装面板的应用验证分开计。未修改生产代码、远端 workflow 或输入期限，
未推送本轮测试补丁，也未重跑远端 CI。Release 仍需准确提交的 CI、包检查和
Ubuntu 24.04 干净安装验收。

## 验证边界

本轮是 Linux 本机安装、私有 X11 应用和固定词句验证，不是个人 GNOME/原生 Wayland、
真实设备 LED、所有应用或真人长期舒适度验收。真实模型生成质量、延迟、云服务、
翻译及其他平台没有由这些离线或受控 HTTP 结果获得验收。
本轮未重测 bottom / auto 布局、真实 IBus 守护进程丢失或服务容器链。
功能成熟度评分保持不变。
