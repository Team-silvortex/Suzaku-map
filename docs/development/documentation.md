# 文档维护

文档按读者任务组织，每项事实保留一个正文来源，其他入口链接它。

## 内容归属

| 内容 | 位置 |
| --- | --- |
| 简介、当前下载和最短上手路径 | 根 README |
| 按任务查找全部文档 | docs/README.md |
| 当前输入、设置和模型使用方式 | docs/users/ 与现有用户指南 |
| 架构、构建、测试、数据格式和维护契约 | docs/development/ |
| 当前功能关系与成熟度 | functional-network.md 与 functional-tensor.json |
| 某版变化、迁移和发布回执 | docs/releases/对应版本.md |
| 原始调查、失败、批次数据和逐轮验收 | docs/history/按年月/ |

现有平铺指南和审计文件保留兼容地址，不为目录整齐而制造一批失效链接。
有明确迁移需要时，应一起更新链接、打包副本和张量 evidence 路径。

## 每次改动

1. 先判断是当前行为变化、源码版本变化，还是一次实验记录。
2. 只改所属正文；其他入口只更新必要链接，不复制整段日志。
3. 历史记录保留日期、准确来源、真实失败和限制，不把局部结果拼成完整验收。
4. 发布说明和当前下载只在发布真实完成后更新；源码版本不自动代表已发布安装包。
5. 更新功能证据时用链接定位完整记录，简短说明证据支持的范围；不因整理文档提高评分。

README 和开发导航应短于 120 行；长命令列表、逐批数量和发布哈希表不回填首页。
词库 README 只保留当前资源概览与维护导航，原始批次数据留在历史记录。

## 链接和归档

使用相对路径链接仓库内文档。源码文件链接可在仓库中阅读，但不意味着二进制包附带源码。
用户操作说明与历史实验分开；代码块中的临时命令不当成活动导航。

2026-10 的整理保留了完整旧入口。归档清单记录来源 Git 提交、原始与归档字节的哈希，
以及逐个链接的可逆重定位；可从归档恢复原始字节核验，不靠重新抄写历史。
这份清单是只读来源记录，后续批次应建立新文件，不修改已归档的记录。

```sh
python3 -B scripts/check-documentation.py
python3 -B scripts/test-documentation.py
python3 -B scripts/test-package-docs.py
python3 -B scripts/check-package-audit-links.py .
python3 -B scripts/functional-tensor.py --check
python3 -B scripts/test-functional-tensor.py
```

链接与归档检查不替代安装包验收。未来包需要包含目录页和子目录资料，
平铺的旧指南副本也必须重定位相对链接；布局和复制的测试由打包工具负责。
