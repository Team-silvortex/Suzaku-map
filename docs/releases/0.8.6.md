# 0.8.6 Everyday vocabulary and Japanese continuation

Suzaku Map 0.8.6 expands everyday English, Chinese and Japanese offline
word/sentence candidates. The Linux / IBus Alpha targets Ubuntu 24.04 amd64
with X11 or GNOME/XWayland. Keep another input method available as a fallback.

## Everyday vocabulary

Six authored data batches cover polite replies, finding places and belongings,
directions, waiting/rescheduling, shopping/payments, public transport and
phone/message contact. Compared with 0.8.5, they add **432 sentences, five
indexed English forms, 224 Chinese readings and 112 Japanese readings**.

Current built-in totals are:

- English: 6,139 indexed forms, 657 contexts and 1,278 sentences.
- Chinese: 2,816 readings, 651 contexts and 1,300 sentences.
- Japanese: 314 readings, 158 contexts and 315 continuation records.

Earlier entries, flags, homophone order and English ranks remain protected.
The English index stays below its unchanged 6,144-form limit; candidate
capacities and model/input budgets do not increase. Fourteen optional
language/topic packages remain separate from the embedded vocabulary.

Vocabulary data remains independent of models, providers, hosts and the
panel. These are finite, project-authored fallback expressions, not
open-ended prediction or a complete dictionary. They do not read contacts,
messages, location or personal typing history, send messages, plan journeys,
query live timetables or make purchases. No model is bundled or required.

## Japanese continuous input

Known authored sentence tails retain Kana grammar rather than being split
by newly added short location nouns. Completing a whole reading no longer
reinterprets its tail as another location word. Genuine partial-word
completions, explicit particles, old homophones and reachable later-page
choices remain available. This is bounded matching against active vocabulary,
not general morphology or arbitrary Katakana-to-Kanji lookup.

Already supported Katakana Word spellings also retain their grammatical tails,
including adopted and mid-draft aliases such as `ニホンゴ` and `ベンキョウ`.
Comparison against an authored sentence recognizes only known Word aliases;
the chosen spelling is not rewritten or generalized into reverse lookup.

Space still continues the draft; deliberate adoption and submission remain
separate. Raw spelling, exact undo, literal/protected input and one-time
commits stay covered by regressions.

## Validation and release gate

Before the version metadata update, the development snapshot passes **1,513
all-feature Rust tests**, with zero failures and 29 explicit fixture/live gates
ignored by the ordinary invocation. Strict all-feature/all-target Clippy and
formatting pass. The complete isolated GTK vocabulary gate passes **147
workflows** across three mixed-language sessions; a separate **53-workflow**
gate loads all fourteen optional packages into private QA data.

The focused private IBus failure diagnostic passes **106 workflows** over
53 fixed samples under actual controlled HTTP 503 and request timeout.
It proves local adoption/undo/continuation/exact commits during model failure,
not the complete native matrix or real-model quality. Synthetic/XTest checks
are not human keyboard, physical device or personal-desktop acceptance.
Detailed scopes and retained failures are in the
[development record](../history/2026-10/pre-reorganization/development.md).

Version metadata is synchronized to **0.8.6**, with macOS/Android build number
**36**. Other locked dependencies and optional package versions are unchanged.
No personal installation is updated by a source push.

After the version update and known-alias tail fix, the full local all-feature
Rust regression passes **1,521 tests**, with zero failures and the same 29
opt-in checks ignored. Strict all-feature/all-target Clippy passes with
warnings denied. This does not replace the exact clean-commit CI or
repeat the earlier GTK/device checks under a new label.

Release assets require the exact clean tagged source commit's full CI,
Linux package checks and clean Ubuntu 24.04 installation/upgrade/removal gate.
Only then publish the `.deb`, binary `.tar.gz` and both SHA-256 files.
A source tag or expiring CI artifact alone does not complete publication;
see the [Linux release requirement](../linux-packaging-data.md).

Native Wayland, real-model semantics/latency, broader Japanese analysis,
non-Linux native behavior and the intermittent upstream IBus daemon abort on
newer local stacks remain outside this release's fixes. See
[known limitations](../known-limitations.md).

## Install or upgrade

After approved 0.8.6 assets appear on the matching
[GitHub Release](https://github.com/chiharu-kiryu/Suzaku-map/releases/tag/v0.8.6),
finish or cancel any draft and fully quit Suzaku before upgrading:

```bash
sha256sum -c suzaku_0.8.6_amd64.deb.sha256
sudo apt install ./suzaku_0.8.6_amd64.deb
/usr/bin/suzaku-panel
```

On first installation, explicitly register as your desktop user, **without
sudo**: `/usr/bin/suzaku-tool linux-register install`, then
`/usr/bin/suzaku-tool linux-register verify`. Installation alone does not
activate an input method. Use the tray to activate Suzaku or restore your
previous input method. Upgrade and restart host/panel together; settings and
offline-pack registrations are retained.

The alternative archive is
`suzaku-0.8.6-x86_64-unknown-linux-gnu.tar.gz`, with its `.sha256` and extracted
`SHA256SUMS`. Verify both before running `./bin/panel`; it is not a universal
static Linux binary. Checksums verify integrity, not publisher signatures.
See [Linux installation and data](../linux-packaging-data.md) for dependencies,
tarball setup and safe removal.
