# 0.10.4 Input reliability

Suzaku Map **0.10.4 / build 54** tightens candidate gestures, native draft
recovery and keyboard/tool handoffs without changing the model contract.

This is a **source-only version**, explicitly selected for commit and push.
It creates no tag, GitHub Release or package and restores no automation. The verified
[0.10.2 Linux Alpha download](https://github.com/Team-silvortex/Suzaku-map/releases/tag/v0.10.2)
remains the installation baseline.

## Input fixes

- Candidate sends use exact source identities instead of normalized captions.
  Enter does not substitute a default local candidate when the displayed card
  is stale or unresolved. Changed payloads, drafts or languages retire held
  gestures and scrolling-preview permission; unchanged refreshes retain it.
- Native keyboard queues keep their own host, context and language. An older
  target's acknowledgement cannot supply another field's draft or block its
  new edits. Opening settings also pauses literal-only pending typing; an
  uncertain same-target operation is not automatically replayed.
- Focus-before-click and redacted native FocusOut updates retain recoverable
  text. A retired draft is restored only by explicitly entering the input
  field while its saved local baseline still matches. New active work wins;
  local editing, clearing and successful commits discard obsolete recovery.
- Candidate-mode Backspace now handles the explicit preceding Space and
  subsequent deletions. Shortcut recording retains every overlapping known
  physical key until its own release, including after save or cancellation.
- Stopping dictation retains an already-arrived partial before insertion;
  leaving its mode stops capture. Handwriting refresh and undo retire old
  candidate gestures and previews, even when recognition keeps the same label.
- Input-method errors in small report windows keep the report's selected text
  size and stay clipped to its body, without covering report controls.

Recovery is a single, most-recent **in-memory** text copy, not persistent
history or the latest authoritative native state. It carries no send state
and is never replayed automatically. Explicit restoration still uses normal
local engine and marked-text synchronization.

## Compatibility and validation

Authored vocabulary, all 25 offline packs, their SDK, prediction v1, default
model budgets and dependencies are unchanged; no configuration migration is introduced.

Versioned local results and their exact scopes are recorded in the
[0.10.4 validation history](../history/2026-11/release-0.10.4.md). Local checks
are not validation of the pushed commit's remote CI. Private X11 events,
synthetic acknowledgements and controlled call sequences do not establish
physical-input, personal IBus, real window-manager, real-model or cross-platform
runtime acceptance. No personal installation, service or configuration is changed.
