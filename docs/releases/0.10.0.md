Chinese and basic Japanese offline fallback work into a selected Linux
representative release, together with a preference-file lock fix. It remains

## Preference-file lock ownership

On Linux, a forked child can inherit the open file description that owns a
preference-file lock until it executes another program. Merely closing the
writer's descriptor can therefore leave that lock held briefly after writer
shutdown. The preference store now records the acquiring process and
explicitly unlocks when that process drops its lease. A child dropping an
inherited lease cannot unlock its parent's active writer. The same ownership
guard covers failed opens and cancelled resets after acquisition.

Lock contention remains `Busy`; other underlying I/O errors retain their
error kind instead of all being reported as contention. New controlled
Linux regressions exercise the real writer with a child paused before exec,
an active writer across child exec, inherited-guard disposal, failed opens,
cancelled reset and error classification.

The controlled inheritance mechanism was reproduced, but the earlier
intermittent `Busy` report did not retain enough evidence to prove it had
this cause. A non-interruption unlock error or abnormal process termination
can still prevent immediate explicit release. Automatic restoration of
disk persistence after a failed startup remains unchanged: an instance that
falls back to memory does not begin persisting later merely because a
competing writer exits.

## Compatibility and test boundaries

Input algorithms, base weights, model/provider protocols, candidate capacity,
six-item paging and work budgets remain unchanged. All **25 recommended
data-only packs** (8 English / 8 Chinese / 9 Japanese) and the offline-pack
SDK remain byte-identical to 0.9.9. The sixteen-installed-pack limit remains
in effect. No model or personal input history is bundled.

Seven new vocabulary integration suites cover fixed word/sentence choices,
complete and selected partial inputs, Pinyin tones, fixed Kana, literal
preservation, adoption/undo, exact single commits, private recommended-pack
coexistence and synthetic unavailable-model fallback. Exact test-only
resource inverses preserve the historical resource contracts.

New authored data can change short-input candidate pools. The English
`reply` vector now contains its two existing Word choices followed by two
new authored sentences. Its compatibility fixture first checks every field
of the complete measured four-row vector before reconstructing the exact
historical two-row vector for the unchanged old fingerprint. This does not
filter runtime candidates or claim arbitrary short-input pools are invariant.

Development preflights caught new contexts that displaced older candidate
choices, including Chinese 取号 and 售后申请 and Japanese 補足説明. Those
unshipped additions were replaced with other existing-head contexts; their
original failures and before/after records remain in the
[development history](../../DEVELOPMENT.md). Prior bounded batch results and
isolated fork experiments are not combined into a new full-version test
total. These fixtures do not establish real-model quality, physical-keyboard,
native Wayland, new performance or personal-installation acceptance.
