# 0.10.2 Model configuration and candidate reliability

Suzaku Map **0.10.2 / build 52** improves model API setup and independent-panel
candidate handling. Local vocabulary remains available without a model.

The selected Linux package release is pending acceptance of the exact source
commit. The verified [0.10.1 Linux Alpha download](https://github.com/Team-silvortex/Suzaku-map/releases/tag/v0.10.1)
remains the installation baseline until publication completes.

## Model API configuration

- Settings expose a read-only configuration-path guide in eight interface
  languages. The CLI adds offline path inspection, validation, configuration
  previews and a terminal setup wizard with explicit save and concurrent-edit
  protection. See the [model setup guide](../model-providers.md).
- Compatible services can use an API base URL or a complete generation URL.
  Two explicit Chat Completions profiles support disabled or low reasoning;
  provider names do not silently choose a profile or trigger retries.
- Optional single-request probes use synthetic input and temporary overrides.
  Configuration and validation do not send requests, read keyring secrets or
  grant cloud consent. Credentials remain outside the settings file.
- In-flight cloud waits support cooperative cancellation and reuse their HTTP
  client. Japanese candidates without a type hint receive a bounded,
  conservative word classification rather than always becoming sentences.

The existing local-first defaults, cloud-consent requirement, prediction v1
contract, 1200 ms candidate deadline and default 256-token budget remain.
Cancellation does not establish that the remote server stopped computing or
billing. Earlier real API observations and their limited quality and latency
scope are preserved in the [model validation history](../history/2026-11/model-api-configuration.md).

## Candidate and status feedback

The independent panel shows its own prediction status; tray feedback identifies
the host snapshot instead of promising that a new AI row was added. Known
localized outer messages preserve raw diagnostic payloads.

Numeric candidate adoption and Enter wait for a valid presented candidate
scene. Enter respects an explicit selection; rejected or unconfirmed delivery
keeps the draft without falling back to another candidate or retrying.
Signal-debug controls update the candidate mirror without replaying the draft;
repeating an unchanged calibrated signal preserves selection, prediction and
translation work. See [panel keyboard behavior](../shortcuts.md#独立面板候选键盘操作).

## Compatibility and release acceptance

The new protocol choices are opt-in settings values. Older binaries do not
recognize them; select a previously supported protocol before downgrading a
configuration that uses either new profile. The wizard does not inject
credentials into an already running host or replace explicit reload and enable
steps. Existing Auto, Ollama and OpenAI-compatible request profiles retain
their behavior. Rust callers exhaustively matching the public `ModelProtocol`
enum must handle its two new variants.

All 25 recommended offline packs, their SDK and the authored vocabulary retain
their contents. Tokio is now a direct runtime dependency using the version
already present in the lockfile, not a dependency-version upgrade.

The package baseline remains **Ubuntu 24.04 amd64 / glibc 2.39 / IBus / X11 or
GNOME/XWayland**, as a Linux Alpha prerelease, not latest stable. Publication
requires all eight remote gates on one clean commit and independent acceptance
of that run's four Linux assets. Publication does not replace the personal
installation, operate input-method services or restore cancelled automation.

Versioned local checks and any release blockers are recorded separately in the
[0.10.2 validation history](../history/2026-11/release-0.10.2.md).
