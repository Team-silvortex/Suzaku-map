# 0.9.1 Everyday composition and continuation sources

Suzaku Map 0.9.1 expands the finite English/Chinese/Japanese fallback for
sharing, finding belongings, borrowing and returning items, and repairs
Chinese authored-continuation sources around ambiguous partial words, plus
a Japanese study-pack pagination regression found by full-version testing.
It remains a **Linux / IBus Alpha**, targeting **Ubuntu 24.04 amd64, X11 or
GNOME/XWayland**. Other platforms' synchronized version numbers do not
establish native input acceptance.

At preparation time the latest downloadable Linux release is **0.8.7**.
The earlier 0.8.8/0.8.9/0.9.0 source work is included, not previously delivered
by a successful 0.9.0 package release. The original 0.9.0 CI failure remains
recorded; neither its artifacts nor the successful parent repair run accepts
this new version. See [development history](../../DEVELOPMENT.md).

## Everyday fallback and character composition

Compared with the **0.9.0 source** baseline, built-in resources add:

- English: **24 contexts and 48 sentences**, with no new indexed forms.
- Simplified Chinese: **88 readings, 24 contexts and 48 sentences**.
- Japanese: **36 readings, 18 contexts and 36 continuations**.

Current totals are **6,143 English indexed forms / 773 contexts / 1,510
sentences**, **3,178 Chinese readings / 767 contexts / 1,532 authored
sentences**, and **522 Japanese readings / 262 contexts / 523 continuation
records**. Counts describe authored records, not language quality or a complete
dictionary. These candidates remain available while optional models are
disabled, missing, failed, timed out or empty.

The independent Chinese readings 借/还/给/书/拿/放/带/用/过/完/回/找/到/家/这/本
allow known readings to compose examples such as `zhe ben shu` → 这本书 and
`wo na zhe ben shu` → 我拿这本书 without a new fixed-phrase entry. Existing
whole words and homophones remain separate candidates. Literal spaces after
adopted Han text are preserved; Pinyin syllable separators retain their
existing conversion semantics. Selection/reseeding tests do not establish
physical-keyboard or IBus/panel workflow acceptance.

## Candidate continuity

Narrowly scoped single-final-character completion conflicts receive two
additional sentence-suggestion slots. Offline, model-merge, preference and
long-tail paths share that policy; it does not pin a particular local pair
over every higher-ranked model suggestion. Bare `ta / hao / you` recover the existing 太好了 / 好久不见 / 优先级
sentence pairs. Compound sources retain a decoder's actual finished-path
boundary; a Sentence-kind Prefix completion is not treated as a finished
branch merely because it is displayed early.

Recovery only uses verified, already visible Word paths and existing authored
contexts, appended with deduplication. Search order, beam/completion limits,
weight formulas, six-slot pages, twelve-candidate lists and model/native
protocols remain unchanged. Source availability expands within these bounds.
New exact readings or recovered sentences can intentionally change scores
or page positions; this is not a promise of identical rankings everywhere.

With the optional Japanese study pack enabled, `きょうかし` once again keeps
both authored 教科書 sentences on the first page. This policy only applies
when the first completion is a unique whole-reading Word correcting a greedy
split into a different word, and its own two sentences are already present.
Simply extending the same written prefix, competing root Words and unfinished
ASCII probes retain their existing rules. The original `kyouyu` and
`ほぞんさ` second-page cases remain protected. Word order/weights and the
four-sentence generation cap are unchanged; higher-weight model sentences
can still compete. This does not promise first-page pairs for every prefix
or broaden the existing 256-character local window or model-request budget.

Builtin **里/那 are not added**. The 里 experiment changed `lian` into 里安
and was rejected. A private 那 pack demonstrates displaced-source protection
and selected-Han continuation, but a long full-Pinyin `na ben shu gei ni`
alternative can still be cut from a full twelve-slot pool. This remains open;
adopting 那/那本书 before continuing is a separately tested engine workflow,
not a fix for every unadopted full-Pinyin branch.

## Boundaries and delivery

The model-independent prediction interface and optional local/authorized-cloud
adapters retain their existing contracts. No model or personal input data is
bundled. The optional data-only catalog is unchanged at **25 packs: 8 English,
8 Chinese, 9 Japanese**, with the same **16 installed-pack limit**, including
disabled packs. SDK and pack format are unchanged; activation still requires
host/panel restart, not hot reload or an executable-plugin system.

The included native-test repair splits the original complete IBus gate into
four private sessions, each retaining the original 120-second bound and
assertions. It changes test isolation, not the user's input-method behavior.
Local full-version validation completed with **2,237 Rust tests passed, zero
failed and 32 explicitly ignored**, **19 private UI checks passed**, and strict
all-target Clippy passed. See [development notes](../../DEVELOPMENT.md) for the
initial Japanese regression and its unchanged red/green fixture. These local
results do not replace exact-commit remote native and package acceptance.

Publication requires this exact clean commit's **linux, linux-apps,
linux-package, secrets, format, both Windows/macOS desktop checks and
linux-artifacts** to succeed. Only that run's accepted artifact may supply
the two packages and their SHA-256 files. Matching manifests, internal
inventory, actual file hashes and clean-container installation/upgrade/removal
must pass before tagging and publishing. This is a Linux Alpha prerelease,
**not latest stable**. Cargo version is **0.9.1**; Android/macOS build is **41**.
See [known limitations](../known-limitations.md) for native Wayland, other
applications, physical ergonomics, broader Japanese analysis and model quality.

## Install or upgrade after publication

Use matching assets from the [0.9.1 Release](https://github.com/chiharu-kiryu/Suzaku-map/releases/tag/v0.9.1)
only after acceptance and publication. Finish/cancel the draft and fully quit
Suzaku first; this source update does not replace a personal installation.

```bash
sha256sum -c suzaku_0.9.1_amd64.deb.sha256
sudo apt install ./suzaku_0.9.1_amd64.deb
/usr/bin/suzaku-panel
```

For a first installation, register as the desktop user **without sudo** using
`/usr/bin/suzaku-tool linux-register install`, then
`/usr/bin/suzaku-tool linux-register verify`. Activation remains an explicit
tray action. Restart host and panel together after upgrading; existing settings
and pack registrations are retained.

The archive is `suzaku-0.9.1-x86_64-unknown-linux-gnu.tar.gz`, with its `.sha256`
and internal `SHA256SUMS`. Verify both before running `./bin/panel`.
See [Linux packaging and data](../linux-packaging-data.md).
