# 0.10.3 Panel recovery and input safety

Suzaku Map **0.10.3 / build 53** improves panel recovery and the handoff between
input, settings and read-only reports. It also separates two private internal
boundaries without changing the model protocol or vocabulary.

This is a **source-only version**, selected for commit and push, not a new
GitHub Release or package publication. The verified
[0.10.2 Linux Alpha download](https://github.com/Team-silvortex/Suzaku-map/releases/tag/v0.10.2)
remains the installation baseline. No new tag, installation or recurring task
is created by this source update.

## Window and settings recovery

- Lost or outdated rendering surfaces are reconfigured even when the window
  dimensions have not changed, and stale presented targets are discarded.
- Reopened settings inherit the live preview, including unsaved changes after
  a save failure, rather than loading older disk values over it.
- Auxiliary-window creation and initialization failures return an error instead
  of panicking. Failed settings requests do not prematurely block native edit
  queues; ordinary redraws do not repeatedly retry a failed window creation.
- Input-method errors delivered to a focused report have their own bounded
  notice in the report body, without changing its snapshot, page or retained
  settings feedback.

## Input and explicit settings commands

Candidate-wheel paging now requires a matching, actually presented candidate
frame. A new page revision, input context or viewport cannot authorize a wheel
operation merely by measuring a layout that has not been displayed.

Explicit main-panel settings commands can replace a report with settings or
close it; ordinary redraws still preserve a report. Explicit opening also works
immediately after folding the panel. Reusing settings requests normal system
focus, without a special focus grab.

Opening settings waits for the auxiliary-window result before ending local IME
preedit: failure retains the unfinished composition, success releases its input
context. F1 and Ctrl+, remain inactive during composition. Reentrant dispatch
does not consume an outer settings request or clear its input state.

## Internal boundaries and compatibility

Local loopback HTTP moves to private `model::local_http`, with the existing
public endpoint helpers and compatibility imports retained. Panel display
settings comparison, application and saving move to private `settings_sync`
methods on the same `PanelState`; native settings acknowledgements retain their
separate owner. See the [architecture guide](../development/architecture.md).

There is no dependency upgrade, new model API, configuration migration or
change to prediction v1, default model budgets, authored vocabulary, the 25
offline packs or their SDK. Platform metadata is synchronized, but this does
not establish new Windows/macOS runtime support.

## Validation and known limits

Independent versioned local results are recorded in the
[0.10.3 validation history](../history/2026-11/release-0.10.3.md). Earlier red/green
tests and their exact scopes remain in the linked architecture history; they
are not combined into a new full-regression total.

The versioned affected-chain run exited normally: 1161 Rust tests across 25
unique result groups passed, with 31 existing explicit ignores and no filtered
tests; private UI checks passed 24/24 and the separate settings chain 4/4.
Strict Clippy and formatting also passed. A broader run printed all successful
result rows but its enclosing process exited 143, so it is explicitly **not**
accepted as a successful full regression. Full remote validation of the pushed
commit remains the responsibility of CI.

The offline-pack regression also adds a final no-wait result drain and synthetic
provider timing diagnostics, retaining its two-second wait budget, all nine
cohorts and the original candidate/error/commit checks. This is test-side
observation hardening, not a new production model timeout or a proven diagnosis
of the earlier intermittent full-suite failure.

Surface recovery is not device-loss reconstruction. Main-window initial GPU
creation failure, arbitrary driver resets and real window-manager acceptance
of focus are not claimed fixed. Synthetic constructor failures and private
Xvfb/X11 tests do not replace physical-input, personal IBus, real-model or
remote package acceptance. No personal installation, service or configuration
is changed.
