Suzaku Map 0.9.3 prepares five finite vocabulary batches and local candidate-query
refinements. It remains a **Linux / IBus Alpha**, targeting **Ubuntu 24.04 amd64,
X11 or GNOME/XWayland**. Synchronized Android/macOS versions are not native
acceptance for those platforms.

**Source preparation:** version **0.9.3 / build 43** passes the complete local
all-features run: **2,456 passed / 0 failed / 32 existing explicit ignores**,
across **240 unique result groups, zero filtered tests**. Separately, **19/19
isolated UI checks** and strict all-target/all-feature Clippy pass.
Remote CI and accepted-package validation must still pass before publication.
The published 0.9.2 packages do not contain these changes.

## Everyday offline fallback

Compared with released **0.9.2** (`4108bc0`), this version adds:

- English: **8 indexed forms, 32 contexts and 64 authored sentences** across
  five additional ordered layers.
- Simplified Chinese: **86 Word readings, 32 contexts and 64 authored sentences**.
- Japanese: **36 Word readings, 30 contexts and 60 authored continuations**.

That is **122 CJK readings, eight English forms and 188 trilingual sentences**.
Totals are **6,151 English forms / 827 contexts / 1,618 sentences (48 layers)**,
**3,330 Chinese readings / 821 contexts / 1,640 sentences**, and
**592 Japanese readings / 309 contexts / 617 continuations**.
Earlier raw data order, separator flags, and the first 6,143 English occurrence
ranks remain protected.

- Meeting coordination: changing a meeting point, taking another route and
  explaining where to wait.
- Calls: reconnecting, changing headphones, screen sharing and reporting
  unclear sound or a weak connection.
- Storage: making room, keeping objects separate, moving them and returning
  them to an agreed place.
- Restocking: remaining supplies, refill packs, spares and shopping reminders.
- Basic washcare and paper: `paper`, `soap`, `shampoo`, `toothpaste`, `tissue`,
  `tissues`, `conditioner`, `mouthwash`; Chinese paper/toiletry Words and
  Japanese シャンプー, リンス, ハンドソープ, ヘアブラシ, ソープケース and 洗顔料.

These are authored input examples, not device control, calls, navigation,
inventory tracking, automatic shopping, product/health advice or open-ended
language generation. Existing Words may gain their own continuations; a new
Word entry does not mean its characters were previously impossible to type.
Romanization remains bounded by existing converter rules, including explicit
long marks. This is not a complete Japanese morphology dictionary or arbitrary
Katakana-to-Kanji reverse lookup.

Local candidates remain independent of optional models and appear immediately
while prediction is disabled, missing, pending, failed, timed out or empty.
The provider-neutral prediction contract is unchanged. No model is bundled,
downloaded automatically or selected as a new hard dependency.

## Local queries and Japanese sentence slots

Immutable startup-catalog indexes avoid repeated English context scans,
filter Chinese continuation contexts by their first Unicode character while
restoring original order, and index Japanese written Word prefixes. They do
not retain typed input or derive ranking from hash-set iteration. Their fixed
storage and first-construction costs are separate from warm query timing.

Historical paired warm release replays measured improvements for these index
changes, but preceded the later Japanese sentence-slot repairs. No new timing
acceptance for final 0.9.3, cold start, UI repaint, native keyboard, IBus or a
real model is claimed. See the [methods and retained measurements](../../DEVELOPMENT.md).

Japanese conversion progress can retain two authored sentence slots after its
typing anchor when the original conversion and both actual local continuations
are proven. A separate narrow case supports a unique whole Word missing one
final long vowel, such as `senganryo` → `洗顔料`. It does not change the greedy
primary `洗顔りょ`, Word weights, or older partial-reading pagination policies.
At six slots, literal input is reserved before surplus alternatives; at the
normal twelve-slot limit, excess alternatives can still be removed. The actual
engine applies preferences before that final limit, not to an already truncated
model-merge pool. Model and preference-ranked sentences still compete: local
authors are not hard-pinned.

## Compatibility and limits

New vocabulary can intentionally enrich short prefixes, change score indices
or replace a last-page alternative. In the reviewed development batches:

- `nihongo wo be` gains `別ルート`; two older sentence scores decrease by 0.5.
- `jyunbi g` / `jyunbi ga` gains more screen-related alternatives; some former
  final rows leave the twelve-item pool.
- `shou na` gains storage-related Words and its two old sentence scores each
  decrease by one. In the nine-pack `nihongo w` pool, a new authored continuation
  replaces the previous final alternative.
- `yobi` gains the independent Word `予備`; `yobidash` has a different greedy
  primary, while `呼び出し` stays selectable on page one at score90.5 rather than91.

The final hygiene replay's **419 complete vectors** match its saved immediate
dirty-before snapshot. That snapshot already contains the other four batches;
it is **not** evidence that every 0.9.2-to-0.9.3 candidate pool is unchanged.
Historical corpus fingerprints and their reviewed exact projections remain;
no blanket golden refresh or expanded decoder/count/time limits is used.

The first versioned full regression found that the new hygiene context
`please check whether we need` crowded an existing private-pack sentence off
page one at the generic `please check whether ` boundary. The new, unreleased
context and its two authored sentences now use the synonymous `please check if
we need`. Their exact fixture data, including the catalog's new hygiene tuple,
changes together; all six hygiene contexts and twelve branches remain covered.
Historical catalog hashes/inverse assertions, the old offline-pack test, ranking policy,
page size and candidate limit are unchanged, and the first failure is retained.

The optional catalog is still **25 unchanged data-only packs**: eight English,
eight Chinese and nine Japanese, with an unchanged SDK and **16 installed-pack
limit**, including disabled packs. Changes apply at host/panel restart; there
is no executable-plugin system, hot reload or automatic package download.

## Install or upgrade only after publication

Expected assets are `suzaku_0.9.3_amd64.deb`,
`suzaku-0.9.3-x86_64-unknown-linux-gnu.tar.gz`, and each package's `.sha256`.
Use only the accepted assets after the 0.9.3 prerelease has actually appeared.

Finish/cancel the draft and fully quit Suzaku before upgrading:

```bash
sha256sum -c suzaku_0.9.3_amd64.deb.sha256
sudo apt install ./suzaku_0.9.3_amd64.deb
/usr/bin/suzaku-panel
```

For first installation, register as the desktop user **without sudo** using
`/usr/bin/suzaku-tool linux-register install`, then
`/usr/bin/suzaku-tool linux-register verify`. Activation remains an explicit
tray action. Restart host and panel together after upgrading; settings and
pack registrations are retained. Archive users must verify the external
checksum and internal `SHA256SUMS` before running `./bin/panel`.
See [Linux packaging and data](../linux-packaging-data.md) and
[known limitations](../known-limitations.md).
