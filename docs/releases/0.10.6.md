# 0.10.6 Candidate and Settings reliability

Suzaku Map **0.10.6 / build 56** is being prepared for commit, push and a
Linux Alpha release. **It is not published yet.** Publication is conditional on
the exact commit's required CI checks and accepted installation packages passing
verification; the release will be a **prerelease, not latest stable**.
The verified [0.10.2 Linux Alpha download](https://github.com/Team-silvortex/Suzaku-map/releases/tag/v0.10.2)
remains the installation baseline. No canceled automation is restored.

## Fixes and diagnostics

- Main-to-Settings commands transfer their finite set of consumed, unreleased
  keys on successful creation or reuse. Real releases delivered to either managed
  window retire the matching ownership; ordinary fresh presses and repeats remain
  usable. Closing Settings immediately recalculates Main's current IME permission,
  without taking focus or replaying suspended native typing.
- Enter/Space button activation retains its key until release, preventing a held
  Space from leaking into the newly focused search field. An uncommitted IME
  search preview no longer overwrites the committed query's scroll position;
  cancellation restores that navigation and committed filtering still clamps it.
- GPU initialization diagnostics identify surface, adapter and device-request
  stages, including the selected adapter before a request fails. Success is quiet
  by default; diagnostic fields and error chains are bounded, and log-write errors
  do not replace the original result. Backend selection, requests, fallback and
  device lifetime are unchanged.
- Empty or unusable structured choices no longer hide useful alternatives in the
  same model response. Existing usefulness checks run before candidate slots and
  choice priority are decided. Text and optional word/sentence type stay bound to
  the first accepted row, not an ignored choice, duplicate or unexamined tail.

## Compatibility and validation

Authored vocabulary, all 25 offline packs, their SDK, public prediction v1,
model budgets and dependencies are unchanged. Candidate scan/output limits and
response-completion guards remain in place; no configuration migration is added.

The NVIDIA Xid 32 / device-initialization failure remains unresolved. Software
graphics results do not establish a hardware fix. Clear's IME-composition
cancellation and late-Commit boundaries, and held-key transfer from a destroyed
standalone report back to Main, are not added by this release. Active scrolling
during composition is not covered by the passive-preview fix.

An independently completed, frozen-source local run passed 3193 Rust tests in
332 unique target groups, with zero failures and 39 existing explicit ignores;
24 mandatory private UI cases and four Settings-chain cases passed separately
on verified software graphics. The earlier terminal-owned run was interrupted
and is retained as incomplete evidence, not combined with these results. Its
signal sender remains unknown. These local results do not replace remote CI or
accepted-package verification.

Final versioned checks are still pending; their scope and later results belong in
the [0.10.6 validation history](../history/2026-11/release-0.10.6.md). Local checks
are distinct from the exact pushed commit's CI and package acceptance. Private
X11 events, controlled IME/acknowledgement sequences and loopback model fixtures
are not physical-input, personal IBus, real window-manager, real-model or
cross-platform runtime acceptance. Personal installation, services and configuration
are not changed by this preparation.
