# 0.8.7 Custom shortcuts and continuous everyday input

Suzaku Map 0.8.7 improves continuous input, shortcut ergonomics and authored
English, Chinese and Japanese fallback vocabulary. This is a **Linux / IBus
Alpha**, targeting Ubuntu 24.04 amd64 with X11 or GNOME/XWayland. Keep another
input method available. Shared version metadata does not qualify other platforms.

## Configurable shortcuts

Settings → Shortcuts records six actions: previous/next candidate, previous/next
page, adopt and English/Chinese language switching. Supported combinations are
Ctrl or Alt, optional Shift, and A–Z or Space, except reserved Alt+Space
combinations. Invalid combinations, duplicate
bindings and conflicts with effective presets are rejected atomically. Recording
cancels on Esc, focus loss, closing settings or IME composition; individual/all
resets preserve the selected standard/home-row preset.

Candidate bindings supplement existing aliases. A custom language binding
replaces Ctrl+Shift+Space until cleared. Switching preserves the latest draft
only after successful asynchronous persistence; held keys remain one-shot through
modifier-release order changes. Privacy, Compose, stale focus and cancellation
boundaries do not apply abandoned settings. Backup/restore preserves and
canonicalizes valid bindings, rejecting invalid or conflicting settings rather
than silently dropping bindings.

These are window/input-context controls, not system-wide hooks or arbitrary
key macros. Desktop/application interception cannot be fully detected. Read
[shortcut scope and examples](../shortcuts.md).

## Everyday fallback and continued writing

Four project-authored batches cover daily routines, borrowing/finding items,
clothing/carrying essentials, and washing/tidying/leaving home. Compared with
0.8.6 they add **196 sentence/continuation records**, four English indexed forms,
106 Chinese readings (including `hai → 还`, `hou → 后`) and 52 Japanese readings.

- English: **6,143** indexed forms, **693** contexts, **1,350** sentences.
- Chinese: **2,922** readings, **687** contexts, **1,372** sentences.
- Japanese: **366** readings, **184** contexts, **367** continuation records.

Old English index positions/ranks, authored record order, full-word choices and
candidate budgets remain protected; bare `hai`/`hou` now prefer `还`/`后`.
The English index is still below its unchanged 6,144-form cap. Fourteen optional
language/topic packs remain data-only and separate. These finite fallback
expressions do not read personal routines or typing history and do not replace
open-ended prediction or complete Chinese/Japanese dictionaries.

Chinese unfinished Pinyin can retain known word/sentence continuations without
losing intentional spaces or adopted mixed-script text. Bounded whole-word
continuations no longer vanish when the correct word lies beyond the first
conversion paths; already-matched homophones keep their earlier pages.
Adoption remains editable, undo preserves complete spelling, and Space continues
the draft rather than submitting it.

In the shared engine, successful committed-context undo now cancels predictions made for obsolete
context while preserving the current draft, displayed candidates and deliberate
choice. No-history undo remains a strict no-op. Controlled regressions protect
long edit/restore ABA, multibyte window boundaries, cleared-field recreation and
late errors as well as successes. No concrete model is required by the protocol.

## Validation and release gate

Detailed first failures, subsequent repairs and exact acceptance scopes are
retained in the [development record](../history/2026-10/pre-reorganization/development.md). Ordinary Rust tests
do not run ignored native/device checks. Source-only fixture guards are not
physical-keyboard acceptance; private IBus and XTest are not personal-desktop,
human comfort or real-model quality acceptance.

The versioned local full all-feature Rust run passes **1,713 tests**, zero
failures, with **30 opt-in checks ignored**. Strict all-feature/all-target Clippy,
formatting, nineteen source/adapter guard suites, the tensor source fingerprint
and 250 audit-report links pass. The checksum-pinned directory secret scan also
passes after a narrowly documented fixed-hash false positive. This does not
replace the exact clean-commit remote native, packaging and installation gates.

Both versioned local full native gates (default and inline preedit) also pass
the complete core plus all 106 HTTP-failure/timeout subcases, retaining each
private session's original 120-second deadline. The first remote run separately
revealed Python 3.12/3.14 AST fingerprint-format differences before native or
packaging checks. A narrow source-guard entry point standardizes only that format,
preserving all five original guard files, frozen hashes, assertions and failure
exit codes. That failed run is not release acceptance; the corrected exact
commit must pass the full remote pipeline before assets are published.
The new format/scope checks and five unchanged wrapped suites pass on both
Python 3.12 and 3.14, **196 checks** in total, without changing historical hashes.

The corrected remote run passes all source, Rust, native, UI and real-application
gates, but its monolithic Linux job reaches the unchanged 40-minute overall limit
during release compilation. Package and clean-installation checks are skipped;
no artifact from that cancelled run is approved. Separate bounded CI lanes now
run the original gate groups on independent Ubuntu 24.04 machines, without
extending any job/session deadline or reducing assertions. A final all-gates
join always reports failure when any required gate is unsuccessful and alone
uploads the accepted package artifact after verified success; its short-lived, explicitly
unaccepted staging input is not a release. The newly corrected exact commit
still requires complete acceptance before any tag or assets are published.

The Linux full native gate now runs core and HTTP-failure cases in separate
fresh private sessions, each retaining its original 120-second deadline and all
assertions. Both must pass. This repairs test orchestration after 0.8.6's remote
Linux timeout; it does not relabel that failed run as successful.

Cargo version is **0.8.7**, macOS/Android build number **37**. Dependency versions
and optional pack versions are unchanged. The exact clean tagged commit must
pass full CI, package-content checks and clean Ubuntu 24.04 installation,
upgrade and removal before publishing the `.deb`, binary `.tar.gz` and both
SHA-256 files. Source tags or expiring CI artifacts alone are not a release.

Native Wayland, live-model semantics/latency, broader Japanese analysis,
non-Linux native behavior and the intermittent upstream IBus daemon abort on
newer local stacks remain outside these fixes. See [known limitations](../known-limitations.md).

## Install or upgrade

Use assets from the matching [0.8.7 Release](https://github.com/chiharu-kiryu/Suzaku-map/releases/tag/v0.8.7)
after its checks pass. Finish/cancel any draft and fully quit Suzaku first:

```bash
sha256sum -c suzaku_0.8.7_amd64.deb.sha256
sudo apt install ./suzaku_0.8.7_amd64.deb
/usr/bin/suzaku-panel
```

For first installation, explicitly register **as your desktop user, without
sudo**: `/usr/bin/suzaku-tool linux-register install`, then
`/usr/bin/suzaku-tool linux-register verify`. Installation alone does not
activate an input method. Tray activation/restoration remains explicit.
Restart host and panel together after upgrading; settings and offline-pack
registrations are retained. This source release does not upgrade your installation.

The alternative archive is `suzaku-0.8.7-x86_64-unknown-linux-gnu.tar.gz` with its
`.sha256` and internal `SHA256SUMS`. Verify both before running `./bin/panel`.
It is not a universal static binary; checksums prove integrity, not signatures.
See [Linux installation and data](../linux-packaging-data.md).
