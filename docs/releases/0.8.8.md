# 0.8.8 Remembered preferences and everyday fallback

Suzaku Map 0.8.8 adds default-on local preference persistence to the Linux input
host, clearer tray feedback and more authored English/Chinese household and
mealtime vocabulary. This remains a **Linux / IBus Alpha**, targeting Ubuntu
24.04 amd64 with X11 or GNOME/XWayland. Keep another input method available.
Shared version metadata does not qualify other platforms.

## Remember confirmed choices across restarts

The Linux host now restores candidate preferences at startup and saves confirmed
changes on a bounded background worker. Input callbacks do not read or write the
cache file. Preferences only reorder existing candidates for the same language,
normalized spelling and candidate; they do not create a personal dictionary,
generate new words or couple the vocabulary to a specific model.

The existing learning boundaries remain: only choices retained in an explicit
submission learn, private fields bypass learning and preference ranking, and
unconfirmed adoption, cancellation and ordinary browsing do not become history.
The cache remains bounded to 2,048 entries, with a 24-hour frequency half-life,
including stopped time. Restoring it does not replace an active draft or undo
state.

Persistence is **enabled by default and can be cleared at any time** through the
tray or `/usr/bin/suzaku-tool preferences clear`. The tray shows remembered entry
count and distinguishes local persistence, memory-only operation, saving,
clearing and file errors. A refresh action updates status without repeating the
clear request; status and owned file diagnostics support all eight UI languages.
The CLI can also query `/usr/bin/suzaku-tool preferences status` without exposing
the cache's fingerprints or text.

A clear succeeds only after file deletion and parent-directory synchronization
are acknowledged. Timeout or disconnection means **unconfirmed**, not deleted.
A later refresh can confirm the exact same host/task receipt if the operation
finishes; a restarted host or unrelated clear cannot confirm the old request.
Stale queued saves cannot recreate the cleared cache, while a later genuinely
confirmed choice can start learning again. Clearing leaves the draft and current
selection intact.

## Sensitive local data, not an input-history file

The default file is `$XDG_STATE_HOME/suzaku-ime/preferences-v1.json`, falling back
to `$HOME/.local/state/suzaku-ime/preferences-v1.json`. An explicit absolute
`SUZAKU_IME_CONFIG` uses an isolated `candidate-preferences` sibling directory
instead, without falling back to personal state. Other hosts remain memory-only.

The versioned file contains a random fingerprint key, keyed fingerprints,
effective frequencies and save time, **not typed text, drafts, pending choices
or undo history**. The key is also stored in the file: this is **not encryption
or anonymization**, and someone with file access can guess common inputs.
Treat it as sensitive local data. It is not automatically included in settings
backups or exports, and deleting it is not secure erasure of filesystem snapshots
or external copies.

Linux storage requires private, owned directories and single-link regular files;
new directories/files use 0700/0600 permissions. A nonblocking exclusive writer
lease, validated atomic publication and dedicated temporary-file recovery avoid
overwriting detected conflicts or restoring partial snapshots. Unsafe, corrupt,
oversized or slow startup files fall back to usable memory-only input with an
error; ordinary typing does not silently replace the rejected file. An explicit
clear can reset an owned/private corrupt cache after validation.

Normal shutdown waits only a bounded time. Forced termination, OOM or a hung
filesystem can lose the latest unconfirmed save and leave sensitive unpublished
staging until the next disk-mode startup or explicit clear. Recovery checks only
the bounded, dedicated preference namespace; it never sweeps unrelated files.
These safeguards do not defend against every hostile same-user filesystem race.

Set `SUZAKU_PREFERENCE_MODE=memory` before starting the host to opt out of disk
access. This does **not** delete an existing file, and clearing in that mode is
memory-only. Clear in the normal disk mode and wait for confirmed success if you
also want to remove saved preferences. See [persistence policy and
limits](../ibus-candidates.md#偏好文件持久化088).

## Household and mealtime fallback

Two project-authored batches cover tidying, dishes, laundry, tableware, serving
food and taking leftovers away. Compared with 0.8.7, they add **48 Chinese
readings and 64 English/Chinese sentences**, with 16 additional contexts in each
language. Examples include `i can wash the dishes`, `could you pass the rice,
please?`, `饭好了`, `帮我盛一碗` and `剩下的打包`.

- English: **6,143** indexed forms, **709** contexts, **1,382** sentences.
- Chinese: **2,970** readings, **703** contexts, **1,404** sentences.
- Japanese remains **366** readings, **184** contexts and **367** continuation
  records; all fourteen optional language/topic pack files are unchanged.

English reuses existing forms and stays below the unchanged 6,144-form cap.
Earlier resource content/order, English index positions and candidate budgets
remain protected. Chinese distinguishes serving `cheng'fan → 盛饭` from leftover
`sheng'fan → 剩饭`; the existing `yi'jia → 衣架` first choice remains ahead of the
new `衣夹` alternative.

Fixed regressions cover unfinished spellings, literal input, adoption and
continued long drafts, exact submission/undo, protected-token and line boundaries,
synthetic provider failures and coexistence with all fourteen recommended packs.
Space still continues a draft rather than submitting it. These finite fallback
examples use no downloaded or personal-history corpus and do not replace
open-ended model prediction or complete Chinese/Japanese dictionaries.

## Install or upgrade

Use assets from the matching [0.8.8
Release](https://github.com/chiharu-kiryu/Suzaku-map/releases/tag/v0.8.8) after all
checks pass and assets are published. Finish/cancel any draft and fully quit
Suzaku first:

```bash
sha256sum -c suzaku_0.8.8_amd64.deb.sha256
sudo apt install ./suzaku_0.8.8_amd64.deb
/usr/bin/suzaku-panel
```

For first installation, register **as your desktop user, without sudo**:
`/usr/bin/suzaku-tool linux-register install`, then
`/usr/bin/suzaku-tool linux-register verify`. Installation alone does not activate
an input method. Tray activation/restoration remains explicit. Restart the host
and panel together after upgrading; settings and offline-pack registrations are
retained. The upgraded Linux host uses the new default-on persistence policy.
Publishing this source release does not update an existing installation.

The alternative archive is `suzaku-0.8.8-x86_64-unknown-linux-gnu.tar.gz` with its
`.sha256` and internal `SHA256SUMS`. Verify both before running `./bin/panel`.
It is not a universal static binary; checksums provide integrity, not signatures.
See [Linux installation and data](../linux-packaging-data.md).
