# 0.9.0 Model boundaries and everyday fallback

Suzaku Map 0.9.0 organizes the model adapter and offline-pack implementation,
expands everyday English, Chinese and Japanese fallback, and protects Japanese
sentence choices while Romaji is still being typed.
It remains a **Linux / IBus Alpha**, targeting Ubuntu 24.04 amd64 with X11 or
GNOME/XWayland. Shared platform version numbers do not establish native support
on other operating systems.

At preparation time, the last downloadable Linux release is **0.8.7**. This
candidate also includes the 0.8.8 and 0.8.9 source work: default-on, clearable
local preference persistence, configurable shortcuts, broader topic packs and
safer continuous editing. See the [0.8.8 notes](0.8.8.md) and
[0.8.9 notes](0.8.9.md) for those changes.

## Model and pack responsibilities

The canonical model adapter now lives under `suzaku_map::model`. Existing
`languages::model` imports and LLaMA aliases remain compatible. Production
input paths use the model-independent prediction request, response, error and
cancellation types directly; the old provider trait and English factories are
isolated in a compatibility adapter. Local discovery, configured cloud consent,
request deadlines and cancellation retain their existing behavior.

Offline-pack format validation, catalog construction, transactional storage
and startup activation have separate private modules behind the same public
API. The catalog still contains **25 authored data packs: 8 English, 8 Chinese
and 9 Japanese**; the installation limit remains **16**, including disabled
packs. Pack changes apply on the next host/panel startup. Pack format, SDK,
configuration format and dependency versions are unchanged.

This is module organization within the existing crate. Some language strategy
and translation-contract dependencies remain; there is no new independently
buildable provider crate or executable plugin system.

## Everyday word and sentence fallback

Compared with the 0.8.9 source baseline, built-in resources add:

- English: **8 contexts and 16 sentences**, reusing existing indexed forms.
- Simplified Chinese: **24 readings, 8 contexts and 16 sentences**.
- Japanese: **84 readings, 42 contexts and 84 continuations**.

English and Chinese additions cover battery, charging, volume and screens.
Japanese extends those devices, visits and counter/parcel errands, weather and
going-out preparation, household cleaning and waste-sorting expressions.
Examples include `my phone battery is lo`, `shou ji kuai mei dian l`,
`raikyaku`, `tenkiyohou`, `soujiki` and `bunbetsu`.

Current totals are **6,143 English indexed forms / 749 contexts / 1,462 sentences**,
**3,090 Chinese readings / 743 contexts / 1,484 sentences**, and
**486 Japanese readings / 244 contexts / 487 continuation records**.
These are authored resource records, not language-quality scores or general
morphological coverage. They remain immediately available when optional models
are disabled, missing, empty or failing. Packages bundle neither models nor
personal input history. Weather and waste examples do not query forecasts,
location or local collection rules.

## Japanese candidate continuity

Unfinished Romaji can use existing spare candidate slots for authored-sentence
branches without displacing primary choices or literal input. The older
`souj` → 掃除 continuations stay on the first page alongside the new 掃除機
completion; the longer word's continuations remain selectable on later pages.
Sentence priority changes only between adjacent words in the same reading
branch. Different branches such as `bas` → 場所 / バス retain their prior order;
same-reading words and already completed queries also retain their order.

Word candidate order and scores, page capacity, complete Kana and terminal-n
behavior, unknown/URL/line boundaries, deliberate adoption, exact submission
and undo remain protected by existing and new regressions. Natural Kana words
such as ほこり and ほうき keep a single literal choice when the input already
equals their spelling. No extra transliteration aliases or larger windows are
introduced by the new vocabulary.

## Validation and publication

Versioned validation results and retained failures are recorded in
[DEVELOPMENT.md](../../DEVELOPMENT.md). The earlier individual architecture and
vocabulary results retain their original scopes; they do not replace acceptance
of this exact release commit. The native vocabulary gate uses six bounded
private sessions with its existing assertions and deadlines.

The complete versioned all-feature Rust suite passes **2,103 tests, zero
failures and 32 explicitly ignored** across 179 result groups. The existing
opt-in native/model checks and private-child fixtures retain their original
scope. Source fingerprint, CI graph, vocabulary-partition and package-shipping
guards also pass locally. Strict all-feature/all-target Clippy and the complete
separate **19-test private UI gate** pass. UI checks use isolated displays and
synthetic events/providers. These results precede remote package acceptance.

Publication requires this clean commit's **linux, linux-apps, linux-package,
secrets, format, both Windows/macOS desktop checks and linux-artifacts** to
succeed. Only that run's accepted artifact may supply the binary `.tar.gz`,
`.deb` and their two SHA-256 files. Checksums, matching manifests and the clean
Ubuntu installation/upgrade/removal checks must pass before release.

Cargo version is **0.9.0**; Android/macOS build number is **40**. This remains a
Linux Alpha prerelease, not the latest stable release. Native Wayland,
physical-device ergonomics, open-ended model quality and broader Japanese
analysis retain the [known limitations](../known-limitations.md).

## Install or upgrade after publication

Use matching assets from the [0.9.0 Release](https://github.com/chiharu-kiryu/Suzaku-map/releases/tag/v0.9.0)
after acceptance and publication. Finish or cancel the draft and fully quit
Suzaku before upgrading:

```bash
sha256sum -c suzaku_0.9.0_amd64.deb.sha256
sudo apt install ./suzaku_0.9.0_amd64.deb
/usr/bin/suzaku-panel
```

On first installation, register as the desktop user, **without sudo**:
`/usr/bin/suzaku-tool linux-register install`, then
`/usr/bin/suzaku-tool linux-register verify`. Activation remains an explicit
tray action. Restart host and panel together after upgrading; existing
settings and pack registrations are retained.

The archive alternative is `suzaku-0.9.0-x86_64-unknown-linux-gnu.tar.gz`, with
its `.sha256` and internal `SHA256SUMS`. Verify both before running `./bin/panel`.
See [Linux packaging and data](../linux-packaging-data.md).
