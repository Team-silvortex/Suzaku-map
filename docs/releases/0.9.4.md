# 0.9.4 Everyday spaces and candidate continuity

Suzaku Map 0.9.4 brings five finite everyday-vocabulary batches and bounded
Japanese candidate-continuity and offline-catalog repairs. It remains a
**Linux / IBus Alpha**, targeting **Ubuntu 24.04 amd64, X11 or GNOME/XWayland**.
Synchronized Android/macOS version metadata is not native acceptance for those
platforms.

**Source preparation: 0.9.4 / build 44.** The complete versioned local run passes
**2,585 tests / zero failures / 32 existing explicit ignores**, across **267
unfiltered result groups**. Strict all-target/all-feature Clippy and **19 exact
isolated UI gates** also pass. Exact-commit remote CI and accepted-package
validation are still pending.
This document does not announce a published tag, release or new download.
The published 0.9.3 packages do not include these changes, and preparation does
not replace the personal installation or alter input services/configuration.

## Everyday offline fallback

Compared with released **0.9.3** (`6edfa3e`), this version adds:

- English: **28 indexed forms, 30 contexts and 60 authored sentences**, across
  five additional ordered layers.
- Simplified Chinese: **60 Word readings, 30 contexts and 60 authored sentences**.
- Japanese: **22 Word readings, 30 contexts and 60 authored continuations**.

That is **82 CJK Word readings, 28 English forms, 90 contexts and 180 trilingual
authored sentences**. Totals are **6,179 English forms / 857 contexts / 1,678
sentences (53 layers)**, **3,390 Chinese readings / 851 contexts / 1,700
sentences**, and **614 Japanese readings / 339 contexts / 677 continuations**.
Earlier resource entries, reading order and flags remain intact, as do all
6,151 earlier English first-occurrence ranks.

- Dressing and clothing fit: zips, buttons, shoelaces, sleeves, pockets and
  everyday fit expressions such as “拉链卡住了” and “鞋带又松了”.
- Room comfort: indoor light, curtains and ventilation expressions such as
  “开窗通通风”, “灯光有点刺眼”, 照明 and カーテン.
- Stationery and writing: `pen`, `pencil`, `eraser`, `ruler`, `sticky` and `ink`;
  “铅笔有点钝了”, “这个字写错了”, 付箋 and 筆箱.
- Reading and book pages: `bookmark`, `pages`, `paperback` and `hardcover`;
  “书签”, “这页还没看完”, 栞, 表紙 and 本棚. `bookmark` already existed in the
  optional English internet pack; it is new to the builtin catalog, not to
  every catalog configuration.
- Balcony plants: `plant`, `soil`, `leaf`, `flower`, `flowers`, `pots`, `watering`
  and `watered`; “花盆”, “叶子”, “帮我拿一下喷壶”, 植木鉢, 水やり and 窓辺.

These are authored input expressions, not device control, reading-state or
inventory tracking, actions on files/bookmarks, horticultural advice, plant
sensing or automatic watering. Existing Words can gain their own continuations;
a new explicit Word entry does not mean its characters were previously
impossible to type. No third-party corpus or model is bundled.

Local candidates remain independent of optional models while prediction is
disabled, missing, pending, failed, timed out or empty. The provider-neutral
model contract is unchanged; no model is downloaded automatically or made a
new hard dependency.

## Bounded candidate-continuity repairs

Japanese sentence-slot eligibility now has a narrow missing-final-`ん` case.
It requires an existing converted stem with its own two distinct authored
continuations, a unique matching whole Word and that Word's actual authored
pair. This supports `kankise` → `換気扇` without changing the greedy conversion
anchor. A broader trial changed older ticket pagination and was rejected:
dictionary-only stems such as the older `joushake` / `seirike` paths retain
their previous policy. Model- and preference-ranked sentences still compete;
local authors are not hard-pinned.

A separate Japanese spare-slot rule restores a proven short parent Word when
a new compound would otherwise remove it. It applies **only at the default
twelve-row limit**, to a last-row Local Word introduced by that spare-fill pass
on page two. Its two-Kana parent must be unique and a strict written prefix of
the compound. Only that final row is replaced, preserving its slot metadata,
earlier rows, primary and raw input. This restores `窓` for the tested `ま`
family/rail configuration without changing limits zero through eleven or
larger explicit limits. Internal offline APIs already support larger limits;
this is not a new universal twelve-row cap or a capacity increase.

## Offline pack validation

The catalog no longer applies the **single-source 64-layer ceiling** to the
combined builtin-plus-pack English catalog. A private merged validation path
uses the bounded maximum **64 + 16 × 8 = 192 layers**. Direct catalog creation
also checks the sixteen-entry limit, including disabled or invalid entries.

Single-source validation still allows at most **64 layers**; each pack retains
its **eight-layer / 2,048-work-unit** limits, with **4,096 active extra units per
language** and **16 installed packs**, including disabled packs. Conflict and
transactional-installation checks remain in force. All **25 recommended
data-only packs** (eight English, eight Chinese, nine Japanese) and all three
SDK files are byte-identical to 0.9.3. There is no executable-plugin system,
hot reload or automatic package download.

## Compatibility and limits

New whole Words can change bounded short-prefix choices, their scores, primary
or page. Earlier source entries and authored sentences are retained; this does
**not** guarantee every earlier generated combination remains in a short-root
candidate pool. Reviewed examples include Chinese `fang jian`, `zhe ji`,
`xian na` and “这本…” prefixes, and Japanese `ueki` / `mad`. Some older
ambiguous generated choices leave the decoder's existing four-completion
window, and some surviving sentences move to page two. `uekibachi` now selects
the exact `植木鉢` instead of the old decomposed primary.

The plants batch's final **419 complete fixed replay vectors** match its saved
immediate dirty-before snapshot. That snapshot already contains the other
four batches; it is not evidence that every 0.9.3-to-0.9.4 candidate pool is
unchanged. Exact test-side projections record reviewed data-enrichment deltas
without refreshing historical hashes or hiding the separate parent-Word
reachability repair. Earlier failed runs and rejected wider repairs remain
recorded in the [development history](../history/2026-10/pre-reorganization/development.md).

The page size remains six, with twelve candidates in the default engine list.
No decoder/beam widening, arbitrary fuzzy Pinyin, complete Japanese morphology
or arbitrary Katakana-to-Kanji reverse lookup is added. Existing smaller-limit
boundaries remain: the new default-limit tests do not promise both authored
sentences for every six-slot query. These changes provide no new UI, native
keyboard, real-model quality, cold-start, latency or personal-installation
acceptance.

## Install or upgrade only after publication

Expected assets are `suzaku_0.9.4_amd64.deb`,
`suzaku-0.9.4-x86_64-unknown-linux-gnu.tar.gz`, and each package's `.sha256`.
Use only the accepted assets after the 0.9.4 prerelease has actually appeared.

Finish or cancel any draft input and fully quit Suzaku before upgrading:

```bash
sha256sum -c suzaku_0.9.4_amd64.deb.sha256
sudo apt install ./suzaku_0.9.4_amd64.deb
/usr/bin/suzaku-panel
```

For first installation, register as the desktop user **without sudo** using
`/usr/bin/suzaku-tool linux-register install`, then
`/usr/bin/suzaku-tool linux-register verify`. Activation remains an explicit
tray action. Restart host and panel together after upgrading; settings and
pack registrations are retained. Archive users must verify the external
checksum and internal `SHA256SUMS` before running `./bin/panel`.
See [Linux packaging and data](../linux-packaging-data.md) and
[known limitations](../known-limitations.md).
